# agent-pipeline-init

Разворачивает в целевом проекте пайплайн сессионной работы: файлы правил, журналы,
накопитель инсайтов, источник правды по именам, машинные гейты и чек-лист закрытия
сессии. Пайплайн переносится **процессно**, без предметной специфики проекта-источника:
экзамены, конспекты, теоремы и прочая специфика недопустимы ни в одном генерируемом
файле. Шаблоны — в `${KIMI_SKILL_DIR}/templates/`.

Сборку файлов выполняет модель (подстановка плейсхолдеров, вырезание блоков, мерж с
существующим AGENTS.md, подбор примеров целевого проекта) — а **верификацию результата
выполняют детерминированные проверки** шага 4. Сборщику верят, но проверяют: гейт,
не поймавший дефектную сборку, не считается гейтом.

## Состав пайплайна

| Компонент | Файл | Шаблон | Модули |
|---|---|---|---|
| Правила сессии | `AGENTS.md` (корень) | `templates/AGENTS.template.md` | всегда |
| Журналы | `TODO.md`, `backlog.md`, `HISTORY.md` (корень) | `templates/TODO.template.md`, `backlog.template.md`, `HISTORY.template.md` | всегда |
| Накопитель инсайтов | `AI.md` + каталог `AI/` | `templates/AI.template.md` | `insights` |
| Источник правды | `docs/glossary.md` | `templates/glossary.template.md` | `glossary` |
| Гейты | `tools/check.sh` | `templates/check.template.sh` | всегда |
| Вне git | `.gitignore` | добавить строки | всегда |

Пайплайн-файлы — локальные записи процесса: они **вне git** (§8 шаблона AGENTS.md) и
не упоминаются в закоммиченном содержимом. `README.md` проекта и материалы их не
видят; имена процессов («петля», «устойчивое состояние») определены в самом
закоммиченном, если на них есть отсылки.

## Зависимости

- **Скилл `review-fix-loop`** — цикл качества из §7 шаблона. Оба скилла живут в
  одном репозитории `heni/agent-skills` (github.com/heni/agent-skills). Установка:

      git clone git@github.com:heni/agent-skills.git ~/agent-skills
      ln -s ~/agent-skills/review-fix-loop ~/.agents/skills/review-fix-loop
      ln -s ~/agent-skills/review-fix-loop ~/.claude/skills/review-fix-loop

  (`~/.agents/skills/` нативно сканируется Kimi Code и Codex CLI, `~/.claude/skills/` —
  Claude Code. Клонировать репо прямо в `~/.agents/skills/` нельзя: скиллы окажутся
  вложены на лишний уровень и не будут найдены.)
- **Совместимость версий:** шаблон рассчитан на петлю с профилями
  `code`/`prose`/`proof`/`config`/`data` и исходами `CLEAN`/`DIMINISHING`/`BUDGET`/
  `ESCALATE`. Обновляя петлю, сверить §7 шаблона с её документацией — иначе
  AGENTS.md молча разойдётся с петлой.

## Порядок работы

### 1. Осмотр — до вопросов пользователю

- Состав проекта: язык, сборка, тесты, доставляемые артефакты и их исходники.
- Существующий `AGENTS.md`: если есть — **не перезаписывать**, мержить: сохранить
  действующие правила, добавить разделы пайплайна, нумерацию разделов пересчитать.
  Итоговую структуру показать пользователю.
- Git: есть ли репозиторий, ремоут, основная ветка.
- **Наличие скила `review-fix-loop`** в окружении (каталог скиллов пользователя).
  Если нет — предложить установку (см. Зависимости). Если пользователь отказался
  или не ответил — собирать без модуля `loop` и записать решение в `TODO.md`
  проекта; иначе ни одна единица не закроется (§7 и §9 требуют статус петли).
- Язык генерируемых файлов — язык проекта (по README и коду); если не выводится —
  язык текущего диалога.

### 2. Интервью — только то, что не выводится из осмотра

Задать одним вызовом (структурированный вопрос или короткий список в диалоге),
с дефолтами. Если пользователь не ответил — взять дефолт и записать принятое решение
в `TODO.md` проекта как открытый пункт:

1. **Команда полной проверки** — дефолт: угадать по экосистеме (`make test`,
   `npm test && npm run lint`, `pytest -q`, …); если не угадывается — `make check`
   как явная заглушка с открытым пунктом «заполнить».
2. **Единица работы**: имя (фича / тикет / глава) и её обязательные артефакты с
   фиксированным порядком сборки. Дефолт: фича; артефакты — план, канонический
   материал (код, документация), проверки, производные выжимки.
3. **Набор модулей**: `full` (glossary + insights + loop) или `core` (только
   журналы, дисциплина утверждений, git, закрытие). Дефолт: `full`. Модуль `loop`
   обязателен в full и выключен, если петля недоступна (шаг 1).
4. **Глоссарий**: вести ли обязательные иноязычные имена терминов (для проектов
   с иноязычной литературой/экосистемой — да; иначе — нет). Дефолт: нет.
5. **Автомерж**: мёржит ли агент PR сам на закрытии сессии (после зелёных гейтов
   и петли), или мерж выполняет человек, а агент открывает PR и передаёт ссылку.
   Дефолт: мержит человек — у разных пользователей преференции разные, выбор за
   ними, не за дефолтом.

### 3. Генерация

- Прочитать шаблоны из `${KIMI_SKILL_DIR}/templates/`, подставить плейсхолдеры
  `{{ИМЯ}}`. Все плейсхолдеры и их значения по умолчанию перечислены в шапке
  `AGENTS.template.md` — саму шапку (служебный комментарий с перечнем плейсхолдеров
  и правилами сборки) в сгенерированный файл **не переносить**: там остаются
  литеральные примеры маркеров, на которые ругается гейт целостности.
- Вырезать блоки `<!-- optional: имя --> … <!-- /optional -->` (целиком) и
  внутриабзацные обёртки `<!-- optional: имя -->фраза<!-- /optional -->` (фразу)
  для выключенных модулей; для ответа об автомеже оставить ровно один блок
  (`merge-auto` или `merge-human`). После вырезания **перенумеровать заголовки
  разделов подряд и все ссылки §N вслед за ними**. Пункты списков написаны как
  «1.» — рендерер нумерует сам, их не трогать.
- `{{PIPELINE_FILES}}` и `{{OPTIONAL_NOTE}}` заполнять по фактическому набору
  модулей (в core — без `AI.md`, `AI/`, глоссария и без слов о них).
- Остальные правки шаблона — минимальны: шаблон и есть текст правил, менять его
  следует только под ответы интервью. Примеры в тексте заменить на примеры из
  целевого проекта, если они есть; примеры из проекта-источника пайплайна не
  переносить.
- `AI/method.md` (пустая глава методики по формату из `AI.template.md`) создавать
  только при включённом модуле `insights`.
- Записать в `tools/check.sh` реальные пары «артефакт : исходники» для свежести
  (из осмотра), пример в шаблоне оставить закомментированным. `chmod +x`.
- Дописать имена пайплайн-файлов в `.gitignore` **до** создания самих файлов,
  затем проверить `git status --untracked-files=all`: пайплайн-файлов в выводе
  быть не должно.

### 4. Верификация

Сборку проверяют детерминированные тесты — каждую **подстановкой дефекта**:
внести нарушение → проверка падает с внятным сообщением → убрать → снова молчит.

1. Прогнать `tools/check.sh` на чистом дереве — молчит, код 0.
2. `tools/check.sh --init full|core` — состав дерева соответствует выбранным
   модулям: в core нет `AI.md`, `AI/`, `docs/glossary.md`, и текст `AGENTS.md`
   не упоминает выключенные модули (`glossary`, `AI.md`, `петл`, `review-fix`).
   Подстановка дефекта: оставить в core-файле ссылку §7 на выключенную петлю —
   проверка обязана упасть.
3. Ссылки на разделы: каждая `§N` в `AGENTS.md` указывает на существующий
   заголовок `## N.`. Подстановка: ссылка на несуществующий раздел → падение.
4. Маркеры сборки: ни одного `<!-- optional` и `<!-- /optional -->` в
   сгенерированных файлах. Подстановка: забытый маркер → падение.
5. Нумерация: заголовки разделов идут подряд без дыр. Подстановка: пропущенный
   номер → падение.
6. `git status` показывает только предназначенные файлы; `git check-ignore`
   подтверждает игнорирование каждого пайплайн-файла.
7. Свежесть по mtime ложно срабатывает после `git clone`/`checkout` (все mtime
   «сейчас»). Если гейт свежести падает на свежесклонированном дереве — чинится
   **пересборкой артефактов**, не `touch`; это ожидаемое поведение, а не дыра гейта.

### 5. Передача

- Показать дерево созданных файлов и одной строкой — что где лежит.
- Принятые на интервью решения и открытые вопросы (включая заглушку проверки, если
  она взята, и выключенный по причине недоступности модуль `loop`) — записаны
  в `TODO.md` проекта.
- Пользователю: прочитать `AGENTS.md`, расширять `tools/check.sh` по мере появления
  новых классов дефектов — каждое расширение с подстановкой. Проверки ссылок §N
  и маркеров остаются в `check.sh` насовсем: они ловат расхождение, когда
  AGENTS.md правят вручную или другим агентом.

## Принципы, которые шаблоны кодируют

- `AGENTS.md` читается целиком каждую сессию → бюджет на правило, а не на файл;
  при переполнении детали вниз, императив наверх, сжатие ради объёма запрещено.
- Машинное — машиной (гейты), содержательное — ревьюером (петля). Петля
  обязательна по каноническим материалам и выжимкам; журналы и минорное ей не
  гоняются — она платит за себя там, где ошибку увидит тот, кто примет работу.
- Журналы растут в разные стороны: `TODO.md` сокращается, `HISTORY.md` нарастает,
  `backlog.md` ждёт осознанного переноса.
- Закрытие сессии — единый чек-лист в конце с машинными критериями (гиты синхронны,
  влитые ветви удалены по счётчику коммитов, пайплайн-файлы вне индекса), а не
  набор правил «по ходу».
- Закоммиченное не ссылается на локальное: модель аудиторий (пользователь /
  будущие агенты / читатель репозитория / внешний потребитель) — §5 шаблона.
- Пайплайн — дисциплина, а не файлы: файлы без исполнения правил не работают.
- Шаблоны кодируют практики, проверенные на нескольких проектах: запрет
  caveat-блоков в исходниках, сырой журнал как источник истины для агрегатов,
  реестр прогонов со ссылками по меткам, атомарные коммиты, бюджет ревью по
  нагрузке файла, тест свежего читателя.

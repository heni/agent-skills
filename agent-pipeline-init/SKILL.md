# agent-pipeline-init

Разворачивает в целевом проекте пайплайн сессионной работы: файлы правил, журналы,
накопитель инсайтов, источник правды по именам, машинные гейты и чек-лист закрытия
сессии. Пайплайн переносится **процессно**, без предметной специфики проекта-источника:
экзамены, конспекты, теоремы и прочая специфика недопустимы ни в одном генерируемом
файле. Шаблоны — в `${KIMI_SKILL_DIR}/templates/`.

## Состав пайплайна

| Компонент | Файл | Шаблон |
|---|---|---|
| Правила сессии | `AGENTS.md` (корень) | `templates/AGENTS.template.md` |
| Журналы | `TODO.md`, `backlog.md`, `HISTORY.md` (корень) | `templates/TODO.template.md`, `backlog.template.md`, `HISTORY.template.md` |
| Накопитель инсайтов | `AI.md` + каталог `AI/` | `templates/AI.template.md` |
| Источник правды | `docs/glossary.md` | `templates/glossary.template.md` |
| Гейты | `tools/check.sh` | `templates/check.template.sh` |
| Вне git | `.gitignore` | добавить строки |

Пайплайн-файлы — локальные записи процесса: они **вне git** (§8 шаблона AGENTS.md) и
не упоминаются в закоммиченном содержимом. `README.md` проекта и материалы их не
видят; имена процессов («петля», «устойчивое состояние») определены в самом
закоммиченном, если на них есть отсылки.

## Зависимости

- **Скилл `review-fix-loop`** — цикл качества из §7 шаблона. Зависимость висячей
  не считается: оба скилла живут в одном репозитории `heni/agent-skills`
  (github.com/heni/agent-skills). Установка: клон репо в `~/.agents/skills/`
  (Kimi Code и Codex CLI видят скиллы там нативно), для Claude Code —
  симлинк `~/.claude/skills/review-fix-loop` на каталог.

## Порядок работы

### 1. Осмотр — до вопросов пользователю

- Состав проекта: язык, сборка, тесты, доставляемые артефакты и их исходники.
- Существующий `AGENTS.md`: если есть — **не перезаписывать**, мержить: сохранить
  действующие правила, добавить разделы пайплайна, нумерацию разделов пересчитать.
  Итоговую структуру показать пользователю.
- Git: есть ли репозиторий, ремоут, основная ветка.
- Язык генерируемых файлов — язык проекта (по README и коду); если не выводится —
  язык текущего диалога.

### 2. Интервью — только то, что не выводится из осмотра

Задать одним вызовом (структурированный вопрос или короткий список в диалоге),
с дефолтами. Если пользователь не ответил — взять дефолт и записать принятое решение
в `TODO.md` проекта как открытый пункт:

1. **Команда полной проверки** — дефолт: угадать по экосистеме (`make test`,
   `npm test && npm run lint`, `pytest -q`, …); если не угадывается — `make check`
   как явная заглушка с открытым пунктом «заполнить».
2. **Единица работы**: имя (фича / тикет / вопрос / глава) и её обязательные
   артефакты с фиксированным порядком сборки. Дефолт: фича; артефакты — план,
   канонический материал, производные выжимки, краткий план.
3. **Набор разделов**: `full` (глоссарий + накопитель + петля качества) или
   `core` (только журналы, дисциплина утверждений, git, закрытие). Дефолт: `full`.
4. **Глоссарий**: вести ли обязательные иноязычные имена терминов (для проектов
   с иноязычной литературой/экосистемой — да; иначе — нет). Дефолт: нет.

### 3. Генерация

- Прочитать шаблоны из `${KIMI_SKILL_DIR}/templates/`, подставить плейсхолдеры
  `{{ИМЯ}}`. Все плейсхолдеры и их значения по умолчанию перечислены в шапке
  `AGENTS.template.md`.
- Блоки, помеченные `<!-- optional: имя --> … <!-- /optional -->`, присутствуют
  только если соответствующий модуль выбран на интервью (`full`/`core`, глоссарий,
  иноязычные имена). Остальные правки шаблона — минимальны: шаблон и есть текст
  правил, менять его следует только под ответы интервью.
- Примеры в тексте заменить на примеры из целевого проекта, если они есть;
  примеры из проекта-источника пайплайна не переносить.
- Записать в `tools/check.sh` реальные пары «артефакт : исходники» для свежести
  (из осмотра), пример в шаблоне оставить закомментированным. `chmod +x`.
- Дописать имена пайплайн-файлов в `.gitignore` **до** создания самих файлов,
  затем проверить `git status --untracked-files=all`: пайплайн-файлов в выводе
  быть не должно.
- Создать `AI/method.md` — пустую главу методики по формату записи из `AI.template.md`.

### 4. Верификация

1. Прогнать `tools/check.sh` на чистом дереве — молчит, код 0.
2. **Каждый гейт — подстановкой дефекта**: внести в дерево нарушение, которое
   гейт обязан поймать (пайплайн-файл в индексе; исходник новее артефакта; отсылка
   к `TODO.md` в закоммиченном файле) → гейт падает с сообщением; убрать дефект →
   снова молчит. Гейт, не поймавший внесённый дефект, не считается гейтом.
3. `git status` показывает только предназначенные файлы; `git check-ignore`
   подтверждает игнорирование каждого пайплайн-файла.
4. Сверить дерево с таблицей «Состав пайплайна»: все файлы на месте, плейсхолдеров
   `{{` в сгенерированных файлах не осталось.

### 5. Передача

- Показать дерево созданных файлов и одной строкой — что где лежит.
- Принятые на интервью решения и открытые вопросы (включая заглушку проверки, если
  она взята) — записаны в `TODO.md` проекта.
- Пользователю: прочитать `AGENTS.md`, расширять `tools/check.sh` по мере появления
  новых классов дефектов — каждое расширение с подстановкой.

## Принципы, которые шаблоны кодируют

- `AGENTS.md` читается целиком каждую сессию → бюджет на правило, а не на файл;
  при переполнении детали вниз, императив наверх, сжатие ради объёма запрещено.
- Машинное — машиной (гейты), содержательное — ревьюером (петля). Петля
  обязательна по каноническим материалам и выжимкам; журналы и минорное ей не
  гоняются — она платит за себя там, где ошибку увидит внешний проверяющий.
- Журналы растут в разные стороны: `TODO.md` сокращается, `HISTORY.md` нарастает,
  `backlog.md` ждёт осознанного переноса.
- Закрытие сессии — единый чек-лист в конце с машинными критериями (гиты синхронны,
  влитые ветви удалены по счётчику коммитов, пайплайн-файлы вне индекса), а не
  набор правил «по ходу».
- Закоммиченное не ссылается на локальное: модель аудиторий (пользователь /
  будущие агенты / читатель репозитория / внешний потребитель) — §5 шаблона.
- Пайплайн — дисциплина, а не файлы: файлы без исполнения правил не работают.
- Шаблоны кодируют практики, проверенные на нескольких проектах: запрет
  caveat-блоков в исходниках, сырой журнал как источник истины для агрегатов,
  реестр прогонов со ссылками по меткам, атомарные коммиты, бюджет ревью по
  нагрузке файла, тест свежего читателя.
